# 亚马逊选品自动化 Skill

## 当前唯一执行流程

本测试版采用截至2026-11-26本轮确认的最新步骤。用户不必选择版本。先读[使用指南](docs/使用指南.md)、[阶段执行顺序](docs/new_workflow_trial.md)，交付前读[验收规范](docs/delivery_checks.md)。只运行用户要求的范围；已有结果从检查点续跑。

最新链路为：模板与数据源检查 → 关键词和类目布局 → 提前打开竞品页、同页取数并启动评论导出 → 导出等待期间截图和填数 → 本地集合链接及卖家精灵市场报告 → 本批评价分析 → 合并评价数据源 → 验收。

这是AI串联已实现脚本的流程。`scripts/run_workflow.py` 只可用明确的 `--steps keyword_research` 复用关键词阶段，不能不带步骤参数执行，也不能用它的旧类目、市场、评论阶段代替本流程。不执行独立市场分析页、Sorftime采集、旧差评缓存、旧竞品总后处理、差评透视、切片器或图片嵌入。

## 自动执行约定

用户提供已填写的工作簿并要求分析后，直接持续执行本次范围，默认完成市场调研、竞品、评价和总结。环境准备、输入读取、页面取数、分析、写表和验收由AI串联，不在准备完、检查完或生成中间JSON后停下来等待再次授权。用户明确只做某一部分时遵从该范围。

站点优先使用用户明确指定值；未指定时先识别商品数据源的Amazon链接，再识别竞品详情链接，均无站点信息才默认US。直接使用 `modules/shared/marketplaces.py` 的站点默认邮编，用户给了邮编则覆盖。模板标题中的示例US不覆盖实际商品链接；已能确定的站点和邮编不再次询问。只有实际无法消解的多站点冲突才询问具体选择。

只读取运行所需的结构、ASIN与字段，不做逐格空值审计，不列出评分、评分数、销量等空值要求用户确认或补齐。正常空值保留缺失语义，真实0保留为0；需要网页补取的字段按现有后备机制自动获取。页名按去除首尾空白后的模块后缀识别，前缀不一致可正常运行，不要求用户改名或授权改名；输出产品名优先使用商品源前缀。识别过程中保留原页名和原文件。

仅在缺少实际必需输入且无法自动取得、登录/权限受阻或真人验证时请求必要帮助。完成一项检查后继续下一项工作，不把正常空白当作阻塞。

## 第一次使用

1. 在当前解压目录读取文件，不使用原作者电脑的绝对路径。工作目录为本Skill目录。先运行 `scripts/check_environment.ps1`，检查Python、Node.js及Chrome。
2. 先检查本项目环境、`.workflow-state/runtime.json` 记录、当前激活环境和用户指定的已有环境；可用则复用。运行 `scripts/setup_first_run.ps1` 会跳过可用Python/Node依赖，缺项才安装到项目内。可传 `-Python`、`-NodeModules` 复用其它目录，不修改外部环境。准备后读取记录的Python路径，并将 `CODEX_NODE_MODULES` 设为记录的依赖目录。推荐Python 3.12、Node.js 22/24、Windows和Chrome。
3. 使用 `scripts/open_sellersprite_login_browser.ps1 -Site US` 打开项目专用浏览器。优先复用同配置的现有浏览器；新启动优先9223，占用时自动尝试9224–9243，仍占用则由系统分配空闲端口。成功后将实际端口、CDP地址和配置目录保存到 `.workflow-state/sellersprite/browser-config.json`，后续脚本默认读取该记录，不能继续硬传9223。同机迁移优先复用本机记录的 `-ProfileDir`，不误开空白配置。
4. 在这个浏览器内安装并登录**卖家精灵插件**，同时核验卖家精灵网页和Amazon登录、站点及配送邮编。网页和插件登录分开核验；插件可用“同步网页端账号”恢复既有登录。脚本通过Playwright连接，不要求安装Codex浏览器操作扩展。
5. 环境检查不等于账号、模板和真实业务已验收。需要登录或真人验证时保留页面，让用户完成后继续；不索要密码、Cookie或验证码。

未提供工作簿时先准备环境；用户已提供已填工作簿并要求分析时，环境就绪后自动继续。需要AI具备本地读写、执行Python/PowerShell/Node及Playwright能力；差评还需要实际子智能体能力。

## 输入、站点与输出

- 使用随包 `assets/产品调研模板.xlsx` 的工作副本和用户商品数据源，详见[模板填写说明](docs/模板填写说明.md)。完整报告需有“市场调研”和“竞品分析”模板页；只有商品源可先生成集合链接/网页报告，不猜造整份模板。
- 商品源至少核对ASIN、商品详情链接、类目路径/节点、品牌、月销量、价格、月销售额、评分数、评分、上架时间等所需字段。商品源与评价数据源分开，不能按相似页名混用。
- 空模板在市场调研A3填写关键词反查ASIN，在竞品分析A1标题填写对比ASIN，两组独立。程序按竞品顺序生成详情链接；继续已有报告时核对标题和链接一致。评论只对本批竞品下载，不扫描全部商品源；临时单商品另建批。
- 运行前记录源文件指纹、站点、邮编、关键词/类目/竞品数量、请求范围和输出目录。用户指定优先，未指定时按商品源/竞品链接识别站点，均无信息才默认美国；邮编自动取站点配置（US为10001），不要求确认。链接生成支持12站，不代表完整采集支持12站；当前新版完整业务验证主要在美国站。
- 原工作簿只读保留。每阶段新建检查点，单一顺序写入工作簿；最终结果与缓存给出绝对路径。完整报告默认放桌面“亚马逊产品调研流程输出表”，本批缓存另建目录，用户指定位置优先。

## 评价分析唯一规则

先勾选插件“翻译标题和内容”再下载，核验文件保存、所属商品和原始数据。默认同时最多2个商品开页及导出，完成一个再补下一个；首个导出启动后做本地指标，首批取证后截图，让等待与填数重叠。文件校验完成后才关该商品页；失败页保留。遇到验证或未完成导出停滞时停止补开，保留检查点并定点继续。空模板先做布局/图片锚点初始化，不能直接套预取入口。

- 仅VP或Vine评论；赞同数降序。好评4–5星取前30条，由主智能体归纳；差评1–3星取前100条。
- 本批使用一个全新上下文差评子智能体，不继承主对话、不读取其它产品旧结论。按ASIN分组传编号评论，单商品独立编号、来源指纹和结果；允许一条评论多个原因。要求“基于所给评论，分点精简总结产品的差评原因，每点15字以内”。
- 子智能体列全每个原因命中的评论序号，主智能体逐点回查全部选样，脚本计算比例。不能把代表性引用数当全部提及数。没有子智能体能力时说明缺点阶段未完成，不静默换旧规则。
- 每商品优点、缺点各一个单元格，格内换行。缺点为“原因（百分比）”，按百分比降序；不显示条数。没有入选差评填 `/`；有差评且全部分析后无具体原因填 `无具体差评原因`；下载失败不能当无差评。
- 总结正文为“总结：实际精简总结”，下一行“改进方式：”，再以1.、2.、3.逐条给建议；只依据本批多商品差评，不加“依据”行。
- 合并全部下载评论回主报告唯一“评价数据源”页，最左列“分析商品 ASIN”标记目标商品。原ASIN空白或其它变体原样保留；末尾仅加“优点归纳、差评原因、分析说明”三列。未入选留空，源表不写百分比、分析编号、入选标记或未入选原因。

## 监控、验收与分发

持续监控命令到结束，约30秒报告实际阶段进展；连续60秒无进展即诊断，失败定点续跑。单次CDP连接最多20秒，最多恢复同一配置重连一次。只断开Playwright连接，不关闭用户浏览器。真人验证由用户手动处理。

按[验收规范](docs/delivery_checks.md)及实际修改范围完成门禁、源指纹、格式、图像像素和代表区域渲染核验。脚本退出、完成下载或生成JSON，都不等于整份报告完成；未验证的新电脑/新站点不报告已验证。

分发方式见[打包说明](docs/distribution.md)。只从确认的源码版本生成独立ZIP，不删除本机浏览器配置、缓存或依赖来打包。真实业务Excel、登录状态和旧评价语义缓存不随测试包发送。未获得本次明确授权不推送GitHub。
