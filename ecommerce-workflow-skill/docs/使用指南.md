# 同事测试版使用指南

本包统一采用2026-11-25确认的最新流程。无需挑选版本，也无需自己研究代码；让具备本地文件和命令行能力的AI读取Skill并执行即可。推荐首次测试美国站。

## 1. 收到压缩包后

1. 把ZIP完整解压到固定目录，例如 `D:\AmazonResearchTest`，不要在压缩包内部运行。
2. 在Codex或其它能运行本地程序的AI工具中，把解压后的项目目录作为工作目录。目录里应能看到 `开始使用.txt`、`README.md`、`codex.md` 和 `ecommerce-workflow-skill`。
3. 保留整个文件夹，不要只发或只复制 `SKILL.md`。程序需要同目录下的脚本、模块和资源。
4. 不必安装Git或登录GitHub。此包是本地测试版；不要用GitHub的main版覆盖它。

包内提供 `ecommerce-workflow-skill/assets/产品调研模板.xlsx`，请复制一份作工作副本，并按[模板填写说明](模板填写说明.md)填入自己的数据。包内没有作者的账号状态、真实商品数据、业务截图或已安装依赖。

## 2. 首次环境准备：复制这段给AI

```text
请阅读当前项目的 README.md、codex.md、ecommerce-workflow-skill/SKILL.md 和 ecommerce-workflow-skill/docs/使用指南.md。
按当前唯一最新版准备这台Windows电脑的测试环境。先检查Python、Node.js、Chrome及我已有的可用环境，能复用就直接复用；缺少的依赖才用setup_first_run.ps1安装到项目内，并完成自检。
如果我已提供填好的Excel并要求分析，环境准备好后自动继续完整分析；尚未提供文件时指导我填写模板。不要推送GitHub。需要登录时指导我在浏览器中完成，完成后自动续跑。
```

基础条件：Windows，推荐Python 3.12、Node.js 22或24、Chrome，能够正常访问Amazon和卖家精灵。安装脚本先复用已有可用环境，不重复安装；确实缺少时只在项目内创建Python环境和安装Node依赖，下载缓存也放在项目内。基础软件未安装时，AI会指出缺项。同事查看和手动调整报告可用Excel或WPS；当前流程不创建原生切片器，不要求为了切片器额外配置COM。

AI必须能读写本地文件、执行PowerShell/Python/Node，并连接项目浏览器。完整差评分析需要子智能体能力；仅聊天、无法操作本地电脑的AI不能直接运行本包。

如果以前用过本工具，把原项目目录告诉AI即可；AI应检查其中的Python及node_modules，使用 `-Python`、`-NodeModules` 复用，并把路径记在当前项目 `.workflow-state/runtime.json`。不要因为当前目录没有 `.venv` 就认定电脑没有可用环境。

## 3. 打开项目浏览器并登录

环境完成后发送：

```text
请打开项目专用浏览器，美国站，配送邮编New York 10001。我要安装卖家精灵插件并登录，先不要开始业务处理。
```

在这个窗口里完成：

1. 从卖家精灵官网提供的插件入口安装**卖家精灵插件**并启用。日常Chrome装过，不代表项目专用窗口也已安装。
2. 登录卖家精灵网页，再打开Amazon页面右侧的卖家精灵面板，检查插件也登录了。若显示“同步网页端账号”，可同步。
3. 登录Amazon并检查左上角配送地址为目标站点的邮编。
4. 确认插件能显示商品数据；评论测试还需要账号有评论下载权限。
5. 完成后回复AI“网页登录和插件均已登录，可以检查”。账号密码和验证码直接在网站输入。

项目浏览器会自动避开被占用的端口并记住实际地址，后续脚本直接读取，用户无需选端口；切换端口仍使用同一份插件和登录配置。当前脚本用Playwright连接专用浏览器，不需要为它另外安装Codex浏览器控制扩展。不要用普通浏览器窗口替代，也不要让两个AI任务同时操作这个专用浏览器。

同一台电脑之后再次使用，应从同一项目目录打开，以保留插件和登录。更换源码目录时让AI复用原配置；新电脑需重新安装插件和登录，不复制同事的浏览器配置。

## 4. 准备输入文件

完整测试需包含当前模板的“市场调研”“竞品分析”页，以及商品数据源页。保留模块后缀、字段名和格式，把自己的数据填进去；页名前缀不必一致，首尾空格自动兼容。评分、评分数、销量等空值正常，无需逐项确认或补齐。

商品源需有ASIN、商品详情链接，以及相应分析需要的月销量、价格、月销售额、品牌、类目路径/节点、评分数、评分、上架时间等。ASIN列不能用父ASIN列代替。市场调研页A3填写用于关键词反查的ASIN；竞品分析页A1标题填写需要对比的ASIN，多个用 `/` 分隔，顺序就是最终报告顺序。首次无需再填详情页链接行，程序会生成。两组ASIN可以不同。

把填好的Excel路径或文件交给AI并要求运行即可。站点优先用用户明确指定值，未指定时先识别商品源链接，再识别竞品链接，都没有信息才默认美国站；邮编自动取已有站点配置（美国10001），有特殊要求再覆盖。AI完成必要读取后自动继续，不停下来要求“确认站点、空白正常、允许修正页名并开始”。真正缺少运行必需结构或站点冲突无法判断时才询问具体问题。

## 5. 第一次建议这样试

先用少量竞品（例如2–3款）检查本机下载、图片和分析，再扩大测试。这只限制你选择的测试竞品，不会把市场报告数据源截断成2–3条。

### 只测试集合链接和网页市场报告

```text
请用我提供的Excel商品数据源测试当前市场报告流程，美国站，邮编10001。
本地读取全部有效ASIN生成集合链接，不操作网页链接生成器；用项目浏览器打开，卖家精灵加载更多直到按钮消失，再生成市场报告并保存评分数、评分值、价格三图。
分别告诉我源ASIN数、前台结果数、插件加载数和报告样本数。不要运行关键词、类目或评论，也不要覆盖原Excel。
```

### 测试完整新版报告

```text
请使用本项目当前最新版自动处理我上传的Excel，完成市场调研、竞品、评价分析及总结。
站点优先按我明确指定的值，否则从商品源或竞品链接识别，无信息时默认美国；邮编自动使用对应站点配置。正常空值和页名前缀差异直接兼容，不要停在预检查等待确认。
从已有结果继续；先准备布局，再提前打开竞品页，同页取数并启动评论导出，等待期间完成截图和填数。
按SKILL.md的最新规则完成九张概览图、最多五项对比、原尺寸浮动主图和类目图、本批评价分析及合并评价数据源。持续监控并完成验收，原文件另存，不推送GitHub。
```

### 只做竞品基础，不分析评价

```text
只处理这份Excel的竞品基础字段、高清主图、产品卖点和最多五项对比维度。缺失数据到对应商品页面补取。
不要下载或分析评论，不填写优缺点和总结。原文件另存，按当前标签动态定位并保留格式。
```

### 中断后继续

```text
请读取本批运行记录和最新成功检查点，说明失败项，只继续尚未完成的部分。
已成功下载的评论、截图和填数不要重跑，不混用其它产品或旧批次的评价结论，最后交付实际完成的范围和文件路径。
```

## 6. 当前结果应是什么样

- 市场调研：关键词、类目、12项整体销售指标、品牌/上架时间六图和卖家精灵三图。整体销售数值显示整数；表头“旺季竞价”实际是卖家精灵最近一期周竞价，不是实时竞价。
- 类目月销量与“数量占比”在同一格分两行，保留底色。
- 集合链接直接从全部源ASIN生成，保序去重，超过200条也不截断。链接ASIN数、Amazon结果数、插件条数和报告样本数可能不同，报告按自己的有效样本作图。
- 竞品主图取详情页高清原文件；类目图和产品图原尺寸浮动，可能暂时遮挡旁边格，之后由你手动调整大小并嵌入。市场调研首格放第一款竞品同图。九张概览图按各自图框放置并保留图片像素。
- 对比维度最多五个；产品未说明的功能会明确写“页面未明确说明……”，带单位的可比较数值局部标红加粗。
- 评价：VP或Vine、赞同数降序，好评4–5星最多30条，差评1–3星最多100条。每商品优点/缺点各一格。缺点按提及百分比降序，每点15字以内；多原因可来自同一评论。
- 无入选差评显示 `/`；有入选差评但无具体原因显示“无具体差评原因”。缺点百分比是入选样本中的提及比例，不代表市场全部消费者的发生率。
- 总结使用“总结：……”和“改进方式：1. … 2. …”的格式，不加依据行。
- 全部原评论合并到一张“评价数据源”，最左列区分分析商品ASIN；末尾只有优点归纳、差评原因、分析说明。未入选分析列留空，原ASIN空白正常保留，源表不显示百分比。

最终给你一份另存的Excel及输出路径；原始下载评论、截图、分析JSON和检查点保存在本批本地目录。若只测网页报告，则给报告链接和三图。运行时不要删除或移动缓存；后续核查需要它们。

## 7. 常见问题

| 现象 | 怎么处理 |
| --- | --- |
| 扩展不见了或登录丢失 | 确认打开的是同一项目专用配置；让AI检查配置路径，避免反复创建新窗口 |
| 网页已登录，插件仍显示登录 | 打开插件面板，使用同步网页端账号或在插件中登录 |
| 9223端口被占用 | 启动器自动选择空闲端口并保存，后续阶段读取实际端口；无需关闭其它程序 |
| 浏览器无法连接 | 让AI运行启动器并读取本机browser-config.json，核对实际端口与配置归属；保留已有环境和登录配置 |
| Amazon出现真人验证 | 在保留的页面手动完成，再通知AI继续失败项 |
| 下载显示100%但没文件 | 等待真正下载完成和校验；保留商品页，不能把进度100%当成功或反复点下载 |
| 评论中文译文为空 | 检查“翻译标题和内容”及翻译服务网络；完整原文可用于分析，但必须记录缺译，不能声称译文已齐全 |
| 原评论ASIN为空 | 保留原值，用最左侧“分析商品ASIN”追溯目标商品 |
| 图片过大挡住数据 | 当前选用原尺寸浮动；在Excel/WPS里按需手动缩放并嵌入 |
| 浏览器缩放或最小化 | 类目截图已做缩放换算；最小化时截图前可能恢复并置前，不承诺一直隐藏截图 |
| AI说生成提示JSON就结束 | 这只是分析准备；要求它实际完成本批子智能体分析、证据校验和写表 |
| 子智能体不可用 | 不能把旧词库当分析结果；先完成独立可做的阶段并明确缺点分析未完成 |
| 保存Excel失败 | 关闭正打开的输出工作簿，把报错和检查点交给AI定点恢复 |

## 8. 测试范围与反馈

已在作者机器验证过新版业务试跑、评论预取与截图/填数重叠、高清主图、动态布局和市场报告链路；最新美国站案例为229个源ASIN→219条插件商品→157个报告样本。12站只验证链接格式，不等于12站完整业务全部跑过。含高清主图的新预取组合尚未重新全量跑完，网页或插件变化也可能需要定点适配。

此包由AI串联各阶段，并非双击自动跑完全部业务。不要让AI无参数启动旧总调度。新电脑安装检查和实际账号登录仍须在同事电脑完成。

反馈时提供：包内 `PACKAGE-MANIFEST.json` 的版本/提交号、站点和邮编、执行范围、报错原文或截图、卡住的阶段、本批记录路径、是否已生成文件。涉及业务数据时先核对分享范围；不要发账号密码、Cookie或整个浏览器配置。
