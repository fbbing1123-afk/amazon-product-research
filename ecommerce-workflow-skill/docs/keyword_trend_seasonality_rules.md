# 关键词趋势旺季判断逻辑

本文档说明 `keyword_research` 的关键词趋势子模块如何回填市场调研页里的以下字段。实现代码仍位于 `modules/keyword_trends`：

- `趋势旺季`
- `淡季月搜索量`
- `旺季月搜索量`
- `旺季竞价`

对应代码位置：

`modules/keyword_trends/excel-sellersprite-trends.py`

## 数据窗口

默认优先使用最近完整年，但只有该年具备 12 个有效月搜索量时才会单独按该年计算。

如果关键词是后收录词，最近完整年没有 12 个有效月份，或关键词只在当前年才开始有有效搜索量，则改用“自关键词收录以来”的数据窗口：

1. 找到第一个有效月搜索量（至少为 `2`，`0` 和 `1` 均不作为收录起点）。
2. 从该月起，一直取到趋势数据中的最新月份。
3. 在这个窗口内计算淡季月搜索量、旺季月搜索量、平均值和趋势旺季。

例如关键词从 `2025-02` 才开始有搜索量，或只从 `2026` 年开始有搜索量，就不会再因缺少上一完整年的数据而写入 `/`；会直接用从首次有效月到最新月的可用趋势计算。

## 数据来源

脚本会从卖家精灵关键词趋势页面抓取关键词的月度搜索趋势数据，并读取 `PPC竞价` 页签中的历史周更竞价数据。

读取 PPC 时需要注意页面动作：进入 `PPC竞价` 页签后，脚本会先读取当前周更 PPC 数据；随后点击页面里的 `查看历史月数据` / `历史月数据` 按钮，再读取历史月度 PPC 数据。月度 PPC 不是进入 `PPC竞价` 页签后天然可见的数据，必须先触发这个按钮。

趋势字段使用同一个关键词对应的数据计算，不依赖产品调研或市场分析模块的产物。

## 优先年份

最近完整年仍是首选窗口。例如当前日期是 2026 年，优先检查 2025 年是否有 12 个有效月搜索量。

只有这个条件满足，才只使用 2025 年 1-12 月数据；否则遵循上面的“数据窗口”规则，从关键词首次有效收录月份开始计算到最新月份。

## 基础指标

对选定数据窗口内的月搜索量计算：

- `low`：最低的正数月搜索量，用于写入 `淡季月搜索量`
- `high`：全年最高月搜索量，用于写入 `旺季月搜索量`
- `avg`：全年月搜索量平均值

搜索量为 `0` 或 `1` 的月份不参与 `low`、`high`、`avg` 及旺季阈值判断；其中 `1` 是卖家精灵已知的异常/占位值，不能作为淡季搜索量或关键词收录起点。

## 无明显趋势

满足以下任意一种情况时，判断为 `无明显趋势`：

1. 最高月搜索量 / 最低正数月搜索量 < `1.5`
2. (最高月搜索量 - 最低正数月搜索量) / 平均月搜索量 < `0.35`

也就是说，如果全年波动不够大，脚本认为这个关键词没有明显旺季。

此时：

- `趋势旺季` 写入 `无明显趋势`
- `淡季月搜索量` 写入 `low`
- `旺季月搜索量` 写入 `high`
- `旺季竞价` 与所有其它关键词一致，默认取最新月份的月度 PPC。旧的周更兜底规则仅在显式启用 `peak-period` 兼容模式时使用。

## 旺季月份

如果关键词不是 `无明显趋势`，则逐月判断是否属于旺季。

某个月会被判断为旺季，需要同时满足：

1. 当月搜索量 >= 全年平均搜索量 * `1.20`
2. 当月搜索量 >= 全年最高搜索量 * `0.65`

对应参数：

```text
PEAK_AVG_MULTIPLIER = 1.20
PEAK_MAX_RATIO = 0.65
```

直白理解：

- 这个月必须明显高于全年平均值，至少达到平均值的 1.20 倍。
- 同时不能只是高于平均值，还要达到全年最高峰的 65% 以上。
- 这套阈值比早期的 `1.05 / 0.60` 更严格，可以减少中高位月份被误判为旺季。

这不是卖家精灵或 Amazon 官方给出的行业公式，而是项目里的经验判断规则。选择这两个条件的依据是：

1. 只看全年最高峰比例，可能会把整体搜索量都很低但接近最高峰的月份误判为旺季。
2. 只看全年平均值倍数，可能会把一个明显低于最高峰的中高位月份误判为旺季。
3. 同时要求 `平均值 * 1.20` 和 `最高峰 * 0.65`，相当于要求该月份既明显高于全年常态，又接近全年高峰区间。
4. 用当前样例数据回测后，早期 `1.05 / 0.60` 会把一些中高位月份纳入旺季；调整后结果更集中，更符合“旺季应是明显高峰月份”的业务直觉。

## 爆发月份

某个月会被判断为爆发月，需要同时满足：

1. 当月搜索量 >= 全年最高搜索量 * `0.90`
2. 当月搜索量 >= 全年平均搜索量 * `1.35`

对应参数：

```text
BURST_MAX_RATIO = 0.90
BURST_AVG_MULTIPLIER = 1.35
```

如果只有单独一个旺季月份，并且它同时是爆发月，则显示为：

```text
5月爆发
```

如果是连续多个月，即使其中部分月份是爆发月，也显示为普通区间，例如：

```text
3-5月
```

## 旺季展示格式

脚本会把连续月份合并显示。

示例：

```text
3月
3-5月
2-3月，6-8月
```

如果没有任何月份满足旺季条件，则显示：

```text
无明显趋势
```

## 跨年旺季

辅助逻辑支持跨年月份分组，例如 12 月和 1 月连续时，可以展示为：

```text
12月-次年1月
```

不过当前主判断函数先按普通连续月份分组，因此常规输出通常仍按目标年份内月份展示。

## 旺季竞价

### 默认：最新月竞价（2026-11-22）

保留模板列名 `旺季竞价`，默认口径更新为每个关键词自己的最新月份月度 PPC。该取数不依赖旺季判断或完整年度搜索量，所有关键词都采用同一规则。

2026-11-22 实测页面提示“PPC 数据现已升级为周更，历史月数据将不再更新”，本次 8 个关键词的月度历史均截至 2025-07。因此“最新月”指月度历史中实际提供的最后月份，不等于当前月份；不能把周更数据伪装为新的月度数据。

1. 在 `PPC竞价` 页签点击 `查看历史月数据`，读取真正的月份标签；周更日期不能被截取成月度数据。
2. 按年月确定最新月份，不按接口返回顺序选取。
3. 只使用该月大于 0 的竞价，同一月份有多个候选值时沿用最大值口径。
4. 最新月为空或为 0 时写 `/`，不退回旧月份，不改用周更 PPC。不能取得月度历史的采集错误需要报告，不能沿用旧单元格值冒充成功。
5. 例如 2026-09 为 3.90，2026-10 为 1.25，则填写 1.25；若 2026-10 为 0，则填写 `/`。

主调度器参数为 `--keyword-ppc-bid-mode latest-month`（默认），趋势脚本参数为 `--ppc-bid-mode latest-month`。下文保留原算法说明，仅适用于显式选择 `peak-period` 时。

### 兼容模式：按旺季区间取数

`旺季竞价` 使用卖家精灵 `PPC竞价` 页签里的历史竞价数据计算。

`0` 不是有效竞价。新收录词尚未积累卖家精灵 PPC 历史时，页面可能返回 `0`；周更与月度 PPC 都会忽略该值，若没有任何大于 `0` 的候选竞价，最终写入 `/`。

优先级：

1. 有明确旺季月份时，优先使用旺季范围内的周更 PPC 数据。
2. 如果旺季范围内没有周更数据，再使用旺季月份对应的历史月度 PPC 数据。
3. 如果关键词是 `无明显趋势`，没有明确旺季月份，则取最近 1 个月内周更 PPC 的最大竞价。
4. 如果无明显趋势且没有可用周更 PPC，再取最新一个月的月度 PPC 最大竞价。
5. 如果以上都没有，写入 `/`。

### 周更 PPC 数据

卖家精灵现在的 PPC 数据通常是周更格式，例如：

```text
2025第31周(07/27~08/01)
```

脚本会把它解析成：

```text
week = 2025-07-27
weekEnd = 2025-08-01
```

然后判断这一周是否和旺季月份有重叠。

只要这一周的日期范围和任意旺季月份重叠，就把该周竞价纳入候选。

最后取所有候选周竞价中的最大值，写入 `旺季竞价`。

### 月度 PPC 数据

如果没有周更 PPC 数据，则使用月度 PPC 数据。脚本会在 `PPC竞价` 页签里点击 `查看历史月数据` / `历史月数据` 后再抓取月度 PPC。

逻辑是：

1. 找到旺季月份对应的 `YYYY-MM`。
2. 取这些月份里的最大竞价。
3. 写入 `旺季竞价`。

## 示例

假设目标年份是 2025 年，某关键词趋势判断结果为：

```text
趋势旺季 = 9-12月
```

脚本会在 PPC 周更数据中查找所有与 2025 年 9 月、10 月、11 月、12 月有重叠的周。

如果这些周的最大竞价是 `3.9`，则：

```text
旺季竞价 = 3.9
```

如果关键词是：

```text
趋势旺季 = 无明显趋势
```

旧逻辑中，没有可匹配的旺季月份时：

```text
旺季竞价 = /
```

兼容模式中，仍然会填写 PPC 参考值：

```text
旺季竞价 = 最近 1 个月周更 PPC 最大 bid
```

如果周更 PPC 不可用，则取最新一个月的月度 PPC 最大 bid；仍不可用才写 `/`。

## 关键词排序与局部刷新

关键词整行按 `旺季月搜索量` 从大到小排列。数值相同保持原顺序，空值和 `/` 排最后；趋势图片、超链接、富文本、合并单元格和行样式跟随关键词，类目区及其它工作表不参与排序。

已有完整趋势结果时，可用 `modules/keyword_trends/refresh_monthly_bids.py` 仅重新读取月度竞价、排序并输出副本。缓存按关键词保存成功结果，中断后显式传入 `--resume` 只补未成功项；不同站点不能共用缓存。每次新的刷新使用新的缓存路径，不把上次月份的缓存用于本次最新数据。

## 当前阈值汇总

| 参数 | 当前值 | 作用 |
| --- | ---: | --- |
| `NO_TREND_MAX_MIN_RATIO` | `1.5` | 全年最高/最低低于该值，认为无明显趋势 |
| `NO_TREND_RANGE_AVG_RATIO` | `0.35` | 全年波动幅度/平均值低于该值，认为无明显趋势 |
| `PEAK_AVG_MULTIPLIER` | `1.20` | 旺季月份必须至少达到平均值的 1.20 倍 |
| `PEAK_MAX_RATIO` | `0.65` | 旺季月份必须至少达到最高峰的 65% |
| `BURST_MAX_RATIO` | `0.90` | 爆发月必须至少达到最高峰的 90% |
| `BURST_AVG_MULTIPLIER` | `1.35` | 爆发月必须至少达到平均值的 1.35 倍 |

## 维护建议

如果后续业务觉得旺季判断太宽或太严，优先调整上表参数，不建议直接改写整套流程。

常见调整方向：

- 旺季太多：提高 `PEAK_AVG_MULTIPLIER` 或 `PEAK_MAX_RATIO`
- 旺季太少：降低 `PEAK_AVG_MULTIPLIER` 或 `PEAK_MAX_RATIO`
- 太容易判断为无明显趋势：降低 `NO_TREND_MAX_MIN_RATIO` 或 `NO_TREND_RANGE_AVG_RATIO`
- 太不容易判断为无明显趋势：提高 `NO_TREND_MAX_MIN_RATIO` 或 `NO_TREND_RANGE_AVG_RATIO`
