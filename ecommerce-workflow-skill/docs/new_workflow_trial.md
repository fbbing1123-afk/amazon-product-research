# 新版全流程试跑与执行入口

2026-11-24按用户最新版模板完成：8个关键词、8个类目、12项整体销售指标、9张概览图、6款竞品基础与5项对比、6份评论下载及评价、跨商品总结。主报告为浮动图；下载评论另存仅追加3列分析的副本。原文件未覆盖，未推送GitHub。

这是主智能体串联多个脚本并处理页面交互的完整业务试跑，包含浏览器恢复、开发及诊断时间，不是纯自动调度耗时。旧总入口仍为原版，不能直接执行旧入口来重现新版结果。

## 执行顺序

1. 读取最新模板和数据源，确定ASIN、站点、邮编与本机项目浏览器配置。复用原Chrome配置及CDP，不创建丢失扩展的新配置；同一浏览器的自动化任务串行，避免评论下载目录被另一CDP连接改变。
2. 关键词沿用现有关键词导出、趋势入口，填8项关键词并排序、校验。此次导出1010条，取8项；导出105.5秒、趋势464.6秒，其它未记录阶段不估算。
3. 类目按现有布局入口扩行和翻译，末级类目绑定Amazon BSR。新版 `modules/product_research/scripts/capture_sellersprite_categories.py` 从卖家精灵插件取图及月销量，展开后固定等20秒，保留逐类目检查点。单批最多5项，可用 `--start` 续跑，截图原像素保留，显示框不超过420×170。
4. `populate_market_summary.py` 按标签填写12项指标，不新增市场分析页。先用 `--input --data-dir` 输出统计与图表数据，再用现有 `chart-runtime/render_section3_echarts.mjs` 生成图；传 `--output --chart-dir` 回填品牌、上架时间6图。右侧结论合并区不得写入。
5. 使用本批源ASIN生成Amazon集合链接，插件“加载更多”直到消失，进入市场分析并打开报告。此段页面交互已真实完成，但尚未沉淀为完整自动入口。报告采用的有效样本可少于加载条数，不强行补齐，也不把源样本数覆盖到网页图表中。
6. 已知报告网址后运行 `capture_sellersprite_report_charts.py --report-url "报告网址" --loaded-count 145 --output-dir "report-charts"`，截取评分数、评分值、价格分布三个canvas。实际样本数写入manifest。最终用 `insert_sellersprite_screenshots.py` 按当前标签位置插入，顺序为Review、Rating、价格；只放图表，保留结论区。
7. 竞品基础字段数据源优先，缺项使用已核验网页数据。`populate_basics.py` 已接入月销量、价格($)、上架时间填表及逐字段fallback；中文卖点与最多5项对比仍由主智能体依据原文组织。Alexa推荐问题用于选维度，不能当作产品支持功能的证据。未知明确写“页面未明确说明……”。
8. 每个竞品运行 `download_sellersprite_reviews.py`，勾选“翻译标题和内容”后下载并验收。保留原文件、空ASIN、共享变体及正式Amazon域名的国际评论。插件可能返回部分空译文；原文完整时按原文分析，并记录缺译数量，不伪造或覆盖源列。
9. 依 [新版评价分析](sellersprite_review_analysis.md) 筛样。一个全新子智能体按ASIN分组分析差评，主智能体归纳好评并复核全部证据。按商品产生独立JSON与评论分析副本；跨商品建议只能来自本批差评。
10. `fill_review_batch.py` 一次填入全部已校验结果及总结，长评价复制模板续行、保持原行高字体、下移后方模块和图片。无缺点只写 `/`。输入须为尚未填评价的浮动图检查点，不能用来重存已有切片器或WPS原生嵌入对象的文件。
11. 最终检查ZIP、公式、关键词、类目、9图、竞品基础/评价、标题格式、指标及评论证据一致性、图片无重复锚点、源数据不变与原文件哈希。按实际影响范围渲染；文件结构和渲染验收不等同于Excel/WPS桌面端验收。

## 后续优化建议

竞品列表确认后，可以提前启动评论下载。下载完成的商品送交独立子智能体分析，同时主智能体完成本地统计、图表或其它填表；同一批仍按ASIN分组汇总。浏览器动作和下载设置需串行管理，最终工作簿由一个写入流程依次合并，避免覆盖。此次仅评估方案，没有改为并行调度。
