# 卖家精灵评论评价分析新版

这是卖家精灵“评论下载”数据源对应的独立分析入口。用户于 2026-11-24 确认以下规则。旧网页逐条抓取版保留，但新版不得调用它的抽样、痛点词库、语义缓存、覆盖率或差评透视流程。

## 筛选口径

每个下载目标 ASIN 单独处理，始终保留原 Excel。

1. 保留 `VP评论=Y` **或者** `Vine Voice评论=Y` 的评论，同时满足时只计一条。
2. 按赞同数数值降序；赞同数相同按源表行号升序，结果可重复。
3. 优点：筛选 4、5 星，取前 **30** 条；不足时全部使用。
4. 缺点：筛选 1、2、3 星，取前 **100** 条；不足时全部使用。
5. 缺点交给全新、独立上下文的子智能体，核心要求原样使用：**“基于我给的评论，分点精简总结产品的差评原因，每点精简在 15 个字以内。”**

赞同数空白视为 0；缺少整列或出现负数、缩写、非整数时停止并核对，不能把未知值冒充 0。空白 ASIN 按之前约定保留，仍属于本次下载目标的导出材料；其它子体 ASIN 也保留原值并提示，不能由语义词库擅自重新分配商品。原始记录不可用其它商品的评论补齐。

先选样再分析。标题和正文都为空的记录保留编号，不能引用为结论证据，也不从低赞评论补位。离题、无明确原因的内容不编造结论。优点沿用每点最多 20 字；缺点每点最多 15 字，均为每点一行、不编号、不附旧版覆盖率。不人为限制结论条数，近义内容合并；证据序号仅保存在 JSON，程序据此把结论对应到原评论行，不把编号写入工作簿。

## 差评原因的提及占比

仅在写入竞品分析表的“缺点”单元格时，在每条原因后显示百分比，如 `说明书缺失（50%）`，不显示 `2/4条` 等计数。原因正文仍最多15字，百分比由脚本附加，不占原因字数；优点不附百分比。

- 分子：本次入选差评中，明确提及该原因的不同评论条数。子智能体必须逐点回查全部样本，列全 `review_numbers`，不能只引用代表性例子。同一评论对同一原因只计一次。
- 分母：该商品按既定规则选出的1–3星VP/Vine差评数，最多100条，不足时用实际条数。入选的空原文或无明确原因评论仍在分母内，不引用为问题证据；不拿全部下载评论、好评或其它商品评论作分母。赞同数只用于选样排序，不给提及数加权。
- 一条评论可同时提及多个原因，各项比例相加可超过100%。百分比保留最多1位小数，按四舍五入显示。提及条数、样本数仅保存在JSON供计算核查，不写入表格。没有入选差评时不编造0%结论。
- 提及占比反映本次样本中的出现频率，具体影响程度仍须结合原因内容判断，也不能外推为所有买家的故障率。

下载评论数据表的“差评原因”列只写纯原因文字，不带百分比或提及条数；竞品分析表的“缺点”才使用“原因（百分比）”格式。两处显示须明确分开。评论原页仍只有三列分析结果，不增加编号、入选标记或未入选说明。

## 准备编号评论

在 skill 根目录用已配置的 Python 执行：

```powershell
python modules/competitor_analysis/sellersprite_review_analysis.py prepare --asin B0XXXXXXXX --export "评论原始导出.xlsx" --output-dir "outputs/review-analysis"
```

每次生成独立目录，包括：

- `packet.json`：只读原始来源、SHA-256、筛选规则、数量、完整选样和编号。
- `advantages.prompt.txt`：当前商品的好评材料。
- `disadvantages.prompt.txt`：当前商品的差评材料及子智能体要求。

没有读取旧痛点 JSON、旧差评页、翻译缓存或其它商品分析结果的路径。插件导出的译文可供参考，语义冲突时按同条评论的原文判断。

## 主智能体编排

1. 主智能体阅读本次 `advantages.prompt.txt`，按其格式保存 `advantages.result.json`。
2. 为本批创建一个差评子智能体，**不继承主对话历史**（支持时使用 `fork_turns="none"`）。单商品传本次 `disadvantages.prompt.txt`；多商品按ASIN分组，每组独立编号并携带自己的 `packet_digest`，不得合并为同一个商品。不得传旧角色 `agent_prompt.md`、旧痛点分组或历史总结。
3. 子智能体只读这批按序号排列的原文和译文，不联网、不搜索、不读项目文件、不改代码，不创建其它子智能体；返回 JSON。主智能体原样保存到 `disadvantages.result.json`。
4. 逐点核对结论与所引评论是否吻合，近义点是否重复、是否把“担心会损坏”写成“已经损坏”；还须回查全部样本，核对各原因的提及序号是否完整。有问题时让该子智能体只按本次证据修正，不用旧词库纠正它。
5. 同一批允许一个子智能体分析多个商品并汇总改进建议，每个商品返回独立结果文件，证据只能引用该ASIN的评论。下一批重新创建上下文；临时指定的单商品单独建批。Python只负责准备、校验、写表，不能把生成提示文件说成已经调用子智能体。环境没有子智能体能力时明确说明尚未完成缺点分析，不静默走回旧版。

结果需包含本次 `asin`、`packet_digest`、`kind`、`reviewed_numbers` 和 `points`。每条 point 包含 `text` 及 `review_numbers`。来源或样本发生变化后必须重新分析，不能改哈希来复用旧结果。校验能证明序号、长度和批次匹配，不能自动证明语义正确，主智能体必须核对原文。

差评有样本时还须返回 `evidence_scope: "all_matching_selected_reviews"`，确认已按新提示完成全部提及核对。旧版代表性引用结果会被拒绝，不能直接补标记来生成比例；应重新交给子智能体分析。脚本从有效序号计算 `mention_count`、`sample_count`、`mention_percent`，不采信智能体自行给出的百分比。该确认字段不替代主智能体的语义复核。

没有符合条件的评论时，主智能体可保存空列表与空 `reviewed_numbers`，不必派空任务。存在样本却无明确可支持结论时，结果必须填写 `no_supported_points_reason`；写表为 `/`，具体原因保留在校验结果 JSON，不能断言商品没有缺点。

## 校验和回填

```powershell
python modules/competitor_analysis/sellersprite_review_analysis.py check --packet "本次目录/packet.json" --advantages "本次目录/advantages.result.json" --disadvantages "本次目录/disadvantages.result.json" --output "本次目录/checked-analysis.json"

python modules/competitor_analysis/sellersprite_review_analysis.py fill --packet "本次目录/packet.json" --advantages "本次目录/advantages.result.json" --disadvantages "本次目录/disadvantages.result.json" --workbook "竞品工作副本.xlsx" --output "新版评价工作副本.xlsx"
```

`check` 同时在输出 JSON 所在目录生成 `<原始评论文件名>_含分析.xlsx`，JSON 的 `annotated_export` 记录其路径。两个输出路径均须尚不存在；重复验收请使用新的输出目录。原始下载文件不覆盖。

`check`、`annotate` 与 `fill` 均重新读取原始导出，核对样本、排序和来源；发现错商品、旧批次、漏读序号、越界证据、重复结论或超长文字即失败。`fill` 每次处理一个商品，多商品按顺序在工作副本上继续回填，不能相互覆盖输出。

写表按“详情页链接”的 ASIN 找列，按“优点”“缺点”实际标签找行，支持前方模块增行后的定位。仅修改该商品两个单元格的文本，保留样式、行高、列宽及其它 XML 部件；拒绝覆盖原表、已存在的输出或猜测缺失/合并单元格。使用 ZIP/XML 局部更新并验收，避免重存工作簿破坏 WPS 图片或原生切片器。

## 在评论原页核查分析

不新建工作表。在原评论页末尾追加以下三列，原评论顺序及源字段保留：

| 新增列 | 内容 |
| --- | --- |
| 优点归纳 | 引用该条评论的优点，多条在同一格换行 |
| 差评原因 | 引用该条评论的纯差评原因，不带百分比或条数，多条在同一格换行 |
| 分析说明 | 仅对入选评论记录已分析、已分析但未被结论引用、原文为空等说明 |

不添加“分析入选”和“分析编号”列，证据序号仍保存在JSON供程序对应原行。未入选评论的三列全部留空，不注明原因，用户可自行筛选原字段。原行 ASIN 为空时仍保留空值，商品归属由原始导出和JSON中的下载目标校验。入选但未被结论引用不能误写为未分析；整组没有可支持结论时保留具体说明，不断言商品没有优缺点。

新增表头继承原表头样式，分析文字自动换行，按需增加行高；原始单元格样式、其它页签、图形及链接部件保留。新增列纳入筛选范围，无冻结设置时冻结首行。采用 ZIP/XML 局部修改，只更新评论页和样式部件，并校验原字段和逐行分析内容。已有分析列的文件不重复追加，须从原始下载文件重新生成；含原生 Table 对象的非标准导出暂不支持。

如只需生成带分析列的评论副本，可单独执行：

```powershell
python modules/competitor_analysis/sellersprite_review_analysis.py annotate --packet "本次目录/packet.json" --advantages "本次目录/advantages.result.json" --disadvantages "本次目录/disadvantages.result.json" --output "评论_含分析.xlsx"
```

## 多商品整表回填与长评价

2026-11-24完整试跑新增 `fill_review_batch.py`。完成各商品 `check` 后，传入本批全部校验结果和基于本批差评生成的总结：

```powershell
python modules/competitor_analysis/fill_review_batch.py --workbook "竞品基础完成.xlsx" --output "评价完成.xlsx" --analyses "商品一/checked.json" "商品二/checked.json" --summary "本批总结.txt"
```

回填前重读评论源文件，核对SHA-256、样本摘要与ASIN，再根据证据重新计算百分比。竞品集合须与模板一一对应。内容超过原行高时复制同格式续行，不截断结论、不缩小字体；合并标签、总结及后方浮动图片随之下移。没有可填写的缺点时只写 `/`，不在表格里添加解释。已验证真实6商品，32条原因扩为4行。

输入应为评价区尚未填写的浮动图片检查点；本入口用openpyxl保存，不适用于已创建切片器或须保留WPS原生嵌入对象的工作簿。三张市场报告截图最后用ZIP入口插入。单商品旧 `fill` 仍只写两个目标单元格且保留其它ZIP部件；长评价或整批报告使用上述入口。独立“只分析缺点”CLI、浏览器下载与智能体分析的自动并行调度尚未实现。

多商品改进建议由本批差评生成，经主智能体核对后提供给批量回填入口；不生成旧差评透视，也未改总调度默认版本。不得随后运行旧 `competitor_analysis/run.py` 将旧缓存结果覆盖回来。完整试跑范围及尚未自动化的部分见 [新版全流程试跑](new_workflow_trial.md)。
