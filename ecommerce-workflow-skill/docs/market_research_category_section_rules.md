# 市场调研第 2 小节：所属平台分类及常用分类节点

本文档说明 `product_research` 模块如何生成市场调研页第 2 小节。

## 数据来源

从数据源 sheet 读取以下字段：

- `类目路径`
- `大类目`
- `月销量`
- 可选翻译字段：`类目路径翻译`、`类目路径中文`、`中文类目路径`、`大类目翻译`、`大类目中文`、`最细类目翻译`、`小类目中文`、`类目中文` 等
- 本地翻译缓存：`resources/category_translations.json`

数据源 sheet 可以叫 `数据源`，也可以叫 `产品名称-数据源`。脚本会优先识别以 `数据源` 结尾的 sheet。

## 去重逻辑

优先从 `类目路径` 超链接中提取 Amazon 末级节点 ID，并按节点 ID 去重：

```text
node=3779891 -> 节点 3779891
```

同一个节点下出现的产品会合并成一行分类节点，即使数据源的 `大类目` 或大类入口链接不同，也不会重复生成相同节点。取不到节点 ID 时，才按去除多余空格并忽略大小写后的完整 `类目路径` 去重。不同节点 ID 即使类目路径文字相同，也保持为不同节点。

如果同一个节点存在多个大类入口，脚本优先选择与类目路径第一级名称一致的 `大类目` 入口。例如路径以 `Health & Household` 开头时，优先使用 `/gp/bestsellers/hpc/节点ID`，而不是其它大类入口。

## 类目占比颜色

生成分类节点时，脚本会按上述去重后的节点计算商品数占比：

- 占比 `> 50%`：I 列 `月总销量` 单元格标记为浅蓝色，表示该小类目是当前样本的主类目。
- 占比 `<= 50%`：I 列 `月总销量` 单元格标记为浅红色，表示该小类目占比较低，更偏可迁移/辅助类目。

这个颜色只改 I 列单元格底色，不改行高、列宽、合并单元格或截图位置。

## 类目层级拆分

`类目路径` 使用英文冒号 `:` 拆分。

示例：

```text
Tools & Home Improvement:Plumbing:Pipes, Pipe Fittings & Accessories:Pipe Insulation
```

会写入为：

```text
一级类目 = Tools & Home Improvement
二级 = Plumbing
三级 = Pipes, Pipe Fittings & Accessories
四级 = Pipe Insulation
```

模板默认 A-E 列放 1-5 级类目。  
如果出现 6 级或更多层级，第 6 级开始写入 J 列、K 列、L 列，以此类推。

脚本会按类目层级逐级补中文翻译到对应单元格里，格式和关键词回填一致：

```text
Tools & Home Improvement
(工具与家居装修)
```

翻译优先级：

1. 优先读取整条路径翻译列，并按 `:`、`：`、`>`、`＞`、`›`、`»` 拆分后与英文层级对齐。
2. 如果没有整条路径翻译列，兼容读取 `大类目翻译` 填第 1 级，读取 `最细类目翻译` / `小类目中文` / `类目中文` 填最末级。
3. 如果数据源没有翻译字段，则读取 `resources/category_translations.json` 里的本地翻译缓存。

Agent 运行规则：默认不调用翻译 API。新数据源出现缓存里没有的英文类目时，不要中断或重跑网页自动化。`fill_custom_template.py` 会输出 `{name}_missing_category_translations.json`，其中列出每个未命中的英文类目层级及其所属路径。脚本完成后，agent 读取该清单并自行翻译，生成 `{"English category": "中文翻译"}` JSON，然后运行 `backfill_category_translations.py --translations <json> --workbook <最终xlsx>`。该工具会把翻译写入 `resources/category_translations.json`，并直接更新最终工作簿中市场调研 sheet 的对应 XML 单元格文字，保留截图、图表、超链接和其他现有图片。缓存补齐后，同一类目后续运行会直接复用缓存。

## 最细类目超链接

脚本会把超链接挂在“最细类目”那个单元格上。

脚本会把最细类目设置为蓝色下划线的超链接样式，方便打开 Amazon 节点页面。

取数逻辑：

1. 从 `类目路径` 单元格的超链接里提取 `node=节点编码`。
2. 读取 `大类目` 单元格的超链接。
3. 用以下方式拼出最细类目链接：

```text
大类目超链接/节点编码
```

示例：

```text
大类目超链接 = https://www.amazon.com/gp/bestsellers/hi
类目路径链接 = https://www.amazon.com/b?node=3226898011
最终链接 = https://www.amazon.com/gp/bestsellers/hi/3226898011
```

如果取不到 `node`，则优先使用 `类目路径` 原超链接；再取不到时使用 `大类目` 原超链接。

## 类目表现和月总销量

默认情况下，第 2 小节只负责：

- 写入类目层级。
- 给最细类目挂 Amazon 节点超链接。

`category_research` 默认负责补充第 2 小节：

- 读取每一行最细类目的 Amazon 超链接。
- 使用项目 Chrome 调试端口打开该 Amazon 类目页，要求该浏览器已安装并启用 softtime/sorftime 插件。
- 等待 softtime/sorftime 插件的 `.fullPanoramaBox` 市场全景区域渲染完成。
  - softtime/sorftime 市场全景截图区域出现后，默认最多再等 30 秒。
  - 完整加载标准：核心文字齐全，并且 canvas 数量和宽高达到要求后，区域尺寸、文字长度、canvas 数量稳定约 2.5 秒。
  - 默认只尝试 1 轮：如果 30 秒内完整加载，会立即截图；如果 30 秒内仍未满足完整状态，也会截图当前区域并继续写入 Excel，避免该类目空缺。
- 将该区域整块截图插入同一行的 `类目表现` 区域（F:H）。
- 从市场全景文本中提取 `月总销量`，写入同一行的 I 列。

建议先用 `--category-overviews-limit 1` 测试一个类目，确认 Amazon 页面、softtime/sorftime 插件和截图尺寸正常后再跑全量。
如果临时不想抓类目概览，可以运行工作流时加 `--no-category-overviews`。

单独运行 `category_research` 时也会先检查数据源/模板里的 WPS `DISPIMG` 图片，并在需要时转换成浮动图片再处理，避免产品图片、关键词趋势图或已有截图在 openpyxl 写表过程中丢失。

第 3 小节的 9 张 ECharts 图表不属于 `category_research`，默认归到 `market_analysis` 前置处理。

## 模板格式保护

当分类节点行数超过模板预留行时，脚本会在第 3 小节前插入新行，并同步移动后续合并单元格。

注意：

- 不会主动改第 2、3、13 行等其它模板行的行高。
- 第 2 小节已有模板行高会保留。
- 新增出来的分类节点行会复制第 2 小节模板数据行样式。
- 插入行时会同步移动后续浮动图片和图表锚点，避免第 3 小节图表压到第 2 小节里。
- 新增分类节点行会额外补齐 A-I 表格边框，并单独补强 F:H 合并区域边框，避免 WPS/Excel 显示外框断线。
